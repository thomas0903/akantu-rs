# fixtures/mesh2

Generated by `oracle/probes/mesh2/generate.sh --out <stage>` (cases in
`oracle/probes/mesh2/cases.txt`, probe `oracle/probes/mesh2/mesh2_probe.cc`)
on an x86_64 Linux virtual machine (AMD Ryzen 9 9950X) with the **pinned**
strict install (D-050:
`/build/install-strict`, `READY` = `cca6e460`, compiled with
`-DEIGEN_NO_CPUID` and the aarch64 Eigen cache sizes; image
`akantu-oracle:dev` amd64 `sha256:2da26d87e063…`), x86_64 Ubuntu 24.04 host,
reference `35a851780d0b9471d258ed53a003ae98aaa95ea0`, probes commit
`f6bd0b3f`. `SCOTCH_PTHREAD_NUMBER=1`, `OPENBLAS_CORETYPE=Haswell`,
`OPENBLAS_NUM_THREADS=1`; the probe also calls
`Eigen::setCpuCacheSizes(16384, 524288, 524288)` (no Eigen kernel is involved
in these quantities). Every case was generated three times with identical
output (D-035). Per-case provenance (command, build, probe version and
sources commit) is in each `manifest.json`.

**History.** The first 24 cases were generated on the superseded *unpinned*
install (`READY` `e168f393`, image `45122c21…`) and then regenerated on the
pinned install: the 881 data
files (480,795 bytes, incl. the 40 VTU/PVTU files of `groups_dump/*`) are
byte-identical, so only their `manifest.json` (provenance) was replaced.

**Cases (46).** Original cases: `queries/*` 11, `groups_dump/*` 2, `scotch/*` 6,
`graphviz/*` 5. Adversarial cases from an independent review (`v88_*`; specs
in `oracle/probes/mesh2/adversarial-cases.txt` and the probe mode
`kinds_group_dump`): group dumps of
quadratic, mixed and wedge meshes and of groups holding cohesive, structural,
segment and point elements (`groups_dump/v88_*`, 6), queries on quadratic 3-D
meshes (2), weighted Scotch partitions at 2 / 4 / 8 parts with dblDump files
whose barycentres exercise the `%.6g` formatting, and reorderings of named-
group, mixed, quadratic, cohesive, structural and element-less meshes
(`scotch/v88_*`, 13), Graphviz of a mixed 3-D mesh (1).

Input meshes are recorded by reference (`inputs[].source`, `sha256`); the
Rust tests read the committed copies of the same files (`fixtures/mesh_utils`,
`fixtures/mesh_io`, `fixtures/model`, `fixtures/meshes`) after checking the
checksum. Files written by upstream (`files/<path>`) are stored as `uint8`
arrays.

Upstream quirks visible in the data: `nb_element/all/*` hold the exception
of `Mesh::getNbElement(_all_dimensions, …)` (UD-669); `scotch/*` show that
`MeshPartitionScotch::reorder` leaves node groups on the old numbering
(UD-670); the renamed-group step is absent (UD-671, use after free).
