# Phase-field oracle records on the PETSc DOF manager with TAO

Output of the probe `oracle/probes/pftao/pftao_probe.cc` (probe version 1),
one JSON file per case, generated by
`AKANTU_SRC_HOST=<akantu-src> oracle/probes/pftao/generate.sh` on an
x86_64 Linux virtual machine (x86-64-v3 host), image `akantu-oracle:dev`
linux/amd64 `sha256:2da26d87e063f3c88264f589cf73381feff583eeaa7770d2e01ae034651d59f5`
(D-050 pin; loaded from an image tarball, SHA-256 `53ca5270…`), configuration **strict** (`install-strict`), Debian PETSc
3.22.5, one MPI process, reference commit
`35a851780d0b9471d258ed53a003ae98aaa95ea0`, probe sources at commit
`42e645dc`. Host-independence pins as the serial PETSc record (`../PROVENANCE.md`): Eigen's cache
sizes pinned in `main`, `OPENBLAS_CORETYPE=Haswell`,
`OPENBLAS_NUM_THREADS=1` (`oracle/scripts/oracle-env.sh`; reported in each
file's `host` and `provenance.blas_pin`). Three runs per case, all
byte-identical (`provenance.identical_runs`, `run_sha256`; D-035). Every
double is stored as its IEEE-754 bit pattern (`bits`) next to a `%.17g`
rendering (`values`, for reading only).

were generated by `AKANTU_SRC_HOST=<akantu-src>

cpl_tao_quadratic_no_split cpl_tao_quadratic_volumetric_deviatoric"
oracle/probes/pftao/generate.sh` on an x86_64 Linux virtual machine
(AMD EPYC 4585PX, x86-64-v3), the same image `sha256:2da26d87…`, strict install (`libakantu.so` SHA-256 `554ecfc7…`),
PETSc 3.22.5, probe sources at commit `084dddce1`, the same pins; three
byte-identical runs per case. Before that, probe version 2 regenerated the
five version-1 records into a scratch directory (`generate.sh --out`):
their `result` and `host` are identical to the files above (only
`probe_version` and provenance differ), so those files are kept unchanged.

The Rust replay (`crates/akantu-couplers/tests/petsc_models.rs`, scenario
`phase_field_tao_oracle`, PETSc tier) refuses nothing about the pin itself
(it runs in the pinned `akantu-rs-petsc:dev` image) and compares **bit for
bit** (damage, energy, loading history) under every phase-field
upstream-compatibility switch and the DOF manager's UD-422 switch
`petsc_row_oriented_blocks`: the oracle is unpatched upstream, which inserts
every elemental block transposed (D-088 (2);
`docs/NUMERICAL_VALIDATION.md`, "PETSc back-end"). The record
`optimal_linear` is also the one-process reference of the distributed
TEST-095 scenario `test_phase_field_optimal_linear_distributed`.
The `cpl_tao_*` records are replayed by the scenario `coupler_tao_oracle`
of the same binary, bit for bit under every upstream switch and UD-422's,
and again with the corrected defaults plus UD-422 (and UD-387 for the
volumetric–deviatoric split) only (`docs/NUMERICAL_VALIDATION.md`).
