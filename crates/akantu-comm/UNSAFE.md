# `unsafe` sites of `akantu-comm`

Every `unsafe` site of this crate is listed below, one row per site
(`scripts/unsafe_inventory.py --check`, run by `cargo test -p
akantu-validation --test unsafe_inventory`, fails when a site is missing,
moved or gone; `--update-lines` rewrites the Line column after an edit
that only moves code).
Each row is also pinned to a fingerprint of its site's code (comments and
whitespace ignored) in `UNSAFE.fingerprints`: a site
whose code changed fails the check, and `--update-lines` does not move its
row, until the row is reviewed and re-pinned with `--refresh <Id>`.
A fingerprint covers the Rust site's own tokens only: not the code around
it that sets up its invariants, and not C sources (here `src/mpi_shim.c`), which the guard
does not read; a change there shows only in the commit's diff and its
review.

**Where `unsafe` is allowed.** `src/lib.rs`:
`#![cfg_attr(not(feature = "mpi"), forbid(unsafe_code))]`,
`#![cfg_attr(feature = "mpi", deny(unsafe_code))]`. Without the `mpi`
feature (the default build) the crate contains no `unsafe` at all. With it,
two places opt out: the module `src/mpi_backend.rs`
(`#![allow(unsafe_code)] // FFI edge`) and the two host-handle imports of
`src/communicator.rs` (`#[allow(unsafe_code)]` on `Communicator::from_mpi`
and `Communicator::from_raw_mpi`). The C side of the FFI edge is
`src/mpi_shim.c` (compiled with `mpicc` by `build.rs`, feature `mpi`).

**Counts** (files under `src/` / under `tests/` and `examples/`): block
57 / 11, `unsafe fn` 2 / 3, `unsafe impl` 3 / 1, `extern` block 3 / 2,
unsafe attribute 0 / 2, foreign-ABI function 4 / 1 — **69 sites in `src/`
(three of them, CM-67…CM-69, in the unit-test module `mod tests` of
`mpi_backend.rs`; CM-68 and CM-69 are safe `extern "C" fn`), 20 test /
example sites**.

## Invariant classes

Most sites share one of these arguments; the rows name the class and add
what is specific to the site.

* **K1 — predefined constant.** Reads an `extern static` of rsmpi's C shim
  (`mpi-sys`: `RSMPI_COMM_WORLD`, `RSMPI_UINT8_T`, `RSMPI_SUM`, …): C
  `const` globals initialised at load time, never written, whose Rust types
  are generated by bindgen from the same `mpi.h` (rsmpi build script). No
  MPI call, no precondition. *Established by* rsmpi's generated bindings
  (type), the C shim (value).
* **K2 — local MPI call on a live communicator.** One MPI call whose
  out-parameters are locals of the calling frame (`&raw mut` of a live
  local, exclusively borrowed for the call) and whose communicator handle is
  alive: (a) **MPI is initialised and not finalised** while the call runs —
  the caller holds an `MpiEnvironment` guard (`MpiBackend::env`,
  `PostedEngine::env`, `MpiInFlight::env`), and the lifecycle finalises only
  when the last guard drops (`Lifecycle::release`; a poisoned lifecycle lock
  freezes the count, an exit-mode refusal is permanent, so a guard is never
  released without its clone having counted); (b) **the handle is valid** —
  `MpiBackend` owns its `OwnedComm`, whose drop queues the single
  `MPI_Comm_free` through `Lifecycle::release_handle` (always before
  `MPI_Finalize`, the guard field dropped after the communicator field);
  the posted-receive engine is pumped only while a slot waits, and
  every waiting slot belongs to a `RecvRequest` that holds a clone of its
  `Communicator` (so the backend and handle outlive the slot) or is
  withdrawn/abandoned on every error path (a poisoned engine is never pumped
  again: `try_lock` skips it); (c) **the thread level permits the call** —
  every call goes through `ThreadPolicy::call` (main thread only under
  `Single`/`Funneled`, the process lock under `Serialized`, re-entrant per
  thread). *Established by* the types (`MpiBackend`, `OwnedComm`,
  `MpiEnvironment`, `RecvRequest`) and the runtime check
  `ThreadPolicy::check`.
* **K3 — non-blocking operation that owns its memory.** `start` /
  `MpiBackend::start` hand MPI the buffers owned by an `MpiInFlight`
  (`bufs: Vec<Vec<u8>>`, `ints: Vec<Vec<c_int>>`, the boxed `comm_out` of
  `MPI_Comm_idup`): heap addresses do not change when the owning `Vec`s or
  the operation move; `allocated()` gives every buffer a real allocation (an
  empty `Vec`'s dangling pointer `(void*)1` is Open MPI's `MPI_IN_PLACE`);
  the request handle is written into `op.req`, which is mutably borrowed for
  the call; the operation is completed (`MPI_Test` loop, `Drop` completes
  too) before its memory is released, or **leaked** with its guard and
  `Serialized` registration on a timeout or an MPI error (`leak`: no MPI
  call, no free). Counts come from the checked `count()` (≤ `i32::MAX`
  bytes); receive sizes come from the checked-collective header (the
  agreed per-rank lengths; `HEADER_BYTES × size` for an **intra**communicator,
  checked at adoption, CM-01). Plus K2 (a)–(c) for the communicator.
  *Established by* the type `MpiInFlight` (ownership, `Drop`), runtime
  checks (`count`, the header agreement, `ensure_intra`).
* **K4 — blocking collective after a checked header** (`MPI_Comm_split`,
  the native-policy reductions): every rank passed the same checked header
  (operation, root, operator, element type, element count, policy;
  `check_entries`), so the call is entered by every rank with the same
  contract; under `Serialized` the rank holds the exclusive registration
  (`ExclusiveGuard`) until the call returned. Plus K2.
* **K5 — emergency and process-exit paths.** POSIX/glibc functions with no
  precondition beyond valid pointers (`_exit`, `write`, `dlsym`,
  `on_exit`/`atexit`), called on paths that must not allocate, lock or
  unwind; callbacks given to C never unwind (`catch_unwind`).
* **K6 — `Send`/`Sync` of a raw handle.** An MPI handle is a process-wide
  identifier, not thread-affine memory; which thread may pass it to MPI is
  decided by the thread level at every call (K2 (c)).
